### Triage a problem

**Site unavailable.** Record the URL and time. Check the IIS pool, deployment status, application log and Windows event log for the first error. If a deployment left the site offline, have the release owner verify the copy before reopening it. Confirm the expected release serves a sign-in page.

**Access denied.** Check the account, environment, action and affected record. Ask the administrator to compare the access level, role grants and ownership rule. Verify access with the intended role or refer the permission request to its owner.

**Missing file or PDF.** Check authorization and the underlying attachment file or object. For an export failure, check that Edge is installed and the application identity can write temporary files. Open a known attachment or export to confirm recovery.

**Integration failure after a move.** Verify the environment, Data Protection identity and protected settings with the settings owner. Follow the server-move procedure and test one controlled operation before resuming scheduled work.

Give support the incident time and time zone, release, screen, expected outcome and redacted error. Use the approved secure channel for credentials.
